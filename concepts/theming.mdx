Shadcn HTML is themed entirely through CSS custom properties. Every color, radius, shadow, font stack, and spacing value is a named token — no hard-coded values exist inside component stylesheets. This means you can retheme the entire component library by replacing a single file. Export a theme from [tweakcn.com](https://tweakcn.com), drop the `:root` and `.dark` blocks into `default-semantic-tokens.css`, and every component updates instantly — zero JavaScript, zero class changes, no component rebuilds.

## The token model

All tokens live in `dist/theme/default-semantic-tokens.css`. The file defines two blocks:

- **`:root`** — light-mode values (active by default)
- **`.dark`** — dark-mode overrides (active when `class="dark"` is on `<html>`)

Components reference tokens with `var(--token-name)` in their own CSS files. Because the cascade flows from `:root` → component, toggling the `.dark` class on `<html>` is the only operation needed to flip the entire UI.

```css
/* How the cascade works */
:root {
  --primary: oklch(0.205 0 0);        /* near-black in light mode */
  --primary-foreground: oklch(0.985 0 0);
}

.dark {
  --primary: oklch(0.922 0 0);        /* near-white in dark mode */
  --primary-foreground: oklch(0.205 0 0);
}

/* Component CSS — reads the active value automatically */
.btn[data-variant="default"] {
  background-color: var(--primary);
  color: var(--primary-foreground);
}
```

## tweakcn.com compatibility

Every token in this system matches the export shape of [tweakcn.com](https://tweakcn.com) exactly. This is intentional — it means any theme you build or download from tweakcn is a drop-in replacement.

<Steps>
  <Step title="Design or choose a theme">
    Visit [tweakcn.com](https://tweakcn.com) and use the visual editor to design your theme, or pick from the community themes gallery.
  </Step>
  <Step title="Copy the CSS export">
    Click **Export → CSS Variables**. tweakcn produces a block with `:root { ... }` and `.dark { ... }` sections in OKLCH color space.
  </Step>
  <Step title="Replace the token file">
    Open `dist/theme/default-semantic-tokens.css`. Replace the `:root` and `.dark` blocks with your copied output. Every component rethemes immediately — no other files need to change.
  </Step>
</Steps>

<Note>
  Preserve the radius, shadow, spacing, and typography tokens that tweakcn may not always include. If your export omits them, keep the existing defaults from `default-semantic-tokens.css` for those sections.
</Note>

## Token boundary rule

Components may only reference tokens that exist in the tweakcn export shape. No new `--*` tokens should be invented. If a component needs a color that has no token (for example, a status green), use a hardcoded CSS value directly in the component file instead of adding a new custom property.

**Why:** tweakcn themes are drop-in replacements. If components referenced tokens that tweakcn doesn't export, swapping themes would leave those variables undefined and break styles.

## Full token reference

### Color pairs — surface / foreground

Every surface token pairs with a foreground token for text and icons placed on that surface.

| Surface token | Foreground token | Usage |
|---|---|---|
| `--background` | `--foreground` | Page background and body text |
| `--card` | `--card-foreground` | Card surfaces and their text |
| `--popover` | `--popover-foreground` | Popover and dropdown surfaces |
| `--primary` | `--primary-foreground` | Primary action backgrounds |
| `--secondary` | `--secondary-foreground` | Secondary action backgrounds |
| `--muted` | `--muted-foreground` | Subdued surfaces and helper text |
| `--accent` | `--accent-foreground` | Hover/focus highlight surfaces |
| `--destructive` | `--destructive-foreground` | Danger/delete action surfaces |

### Utility tokens

| Token | Purpose |
|---|---|
| `--border` | Default border color for all component edges |
| `--input` | Input field border color |
| `--ring` | Focus ring outline color |

### Sidebar tokens

The sidebar has its own isolated token set, following the same surface/foreground pair convention.

| Token | Pair |
|---|---|
| `--sidebar` | `--sidebar-foreground` |
| `--sidebar-primary` | `--sidebar-primary-foreground` |
| `--sidebar-accent` | `--sidebar-accent-foreground` |
| `--sidebar-border` | — |
| `--sidebar-ring` | — |

### Chart tokens

Five sequential chart colors for data visualization components.

| Token | Description |
|---|---|
| `--chart-1` | Lightest — `oklch(0.81 0.10 252)` |
| `--chart-2` | `oklch(0.62 0.19 260)` |
| `--chart-3` | `oklch(0.55 0.22 263)` |
| `--chart-4` | `oklch(0.49 0.22 264)` |
| `--chart-5` | Darkest — `oklch(0.42 0.18 266)` |

### Typography tokens

Font stacks as CSS custom properties. Replace these in a theme to change typography globally.

| Token | Default stack |
|---|---|
| `--font-sans` | `ui-sans-serif, system-ui, -apple-system, …` |
| `--font-serif` | `ui-serif, Georgia, Cambria, …` |
| `--font-mono` | `ui-monospace, SFMono-Regular, Menlo, …` |

### Radius scale

Set `--radius` to retheme all border radii. The derived values are computed from it automatically.

| Token | Computation | Default |
|---|---|---|
| `--radius` | Base value | `0.625rem` |
| `--radius-sm` | `calc(var(--radius) - 4px)` | `0.375rem` |
| `--radius-md` | `calc(var(--radius) - 2px)` | `0.5rem` |
| `--radius-lg` | `var(--radius)` | `0.625rem` |
| `--radius-xl` | `calc(var(--radius) + 4px)` | `0.875rem` |

### Shadow scale

Theme-aware shadows from barely-visible to highly elevated.

| Token | Elevation |
|---|---|
| `--shadow-2xs` | Hairline |
| `--shadow-xs` | Minimal |
| `--shadow-sm` | Subtle |
| `--shadow` | Default |
| `--shadow-md` | Medium |
| `--shadow-lg` | Large |
| `--shadow-xl` | Extra large |
| `--shadow-2xl` | Maximum |

### Spacing & tracking

| Token | Value | Usage |
|---|---|---|
| `--spacing` | `0.25rem` (4 px) | Base unit for spacing utilities |
| `--tracking-normal` | `0em` | Default letter-spacing |

## Swapping themes: step-by-step

<Steps>
  <Step title="Open tweakcn.com">
    Go to [tweakcn.com](https://tweakcn.com). Design a custom theme or browse the community gallery and select one you like.
  </Step>
  <Step title="Export CSS variables">
    Use the **Export** panel and choose **CSS Variables**. Copy the complete output — it will contain `:root { ... }` and `.dark { ... }` blocks.
  </Step>
  <Step title="Replace default-semantic-tokens.css">
    Open `dist/theme/default-semantic-tokens.css`. Replace the `:root` and `.dark` color blocks with your pasted output. Keep the radius, shadow, spacing, typography, and tracking sections intact if the export omits them.
  </Step>
</Steps>

## Overriding individual tokens

You don't have to swap the entire theme. Add a stylesheet **after** `default-semantic-tokens.css` and override specific variables:

```html
<link rel="stylesheet" href="dist/theme/default-semantic-tokens.css">
<style>
  :root {
    --primary: oklch(0.55 0.2 250);
    --primary-foreground: oklch(1 0 0);
    --radius: 0.5rem;
  }
</style>
```

<Tip>
  Override tokens in `:root` for light mode and mirror the change in `.dark` if you want consistent dark-mode behaviour. Forgetting the `.dark` override is the most common theming mistake.
</Tip>
